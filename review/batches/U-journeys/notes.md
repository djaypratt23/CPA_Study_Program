# U-journeys — usability review, journeys 1–8

Setup: `dist/` as built at HEAD, served by `vite preview --port 4173 --strictPort` (no rebuild). Driven with the global Playwright install (Chromium 1194, headless) at desktop 1366×900 and phone 390×844 (isMobile, hasTouch, DPR 2). A fresh browser context per journey; console errors, page errors and failed requests were captured per journey into `logs/*.log` (and full stdout of the mock run in `logs/j6-run.txt`). Scripts: `scripts/lib.cjs` (helpers), `scripts/jN*.cjs` (one per journey), `scripts/tbsfill.cjs`, `scripts/tbs_perfect.ts`, `scripts/findings_list.py` → `findings.jsonl`. Screenshots: `review/screens/uj-*.png`. The session was interrupted several times by usage limits and a worker restart; each time the preview server was restarted on the same port from the same `dist/`, and the journey in progress was re-run from a fresh context. The system clock moved on between sessions (runs span 2026-10-07 to 2026-10-29); every run used the live clock, so day counts in screenshots differ (e.g. "100 days" vs "79 days" to a 2027-01-15 exam).

Answers were chosen from the content JSON (`[data-choice]` ids), so "right" and "wrong" answers are deliberate.

## Journey 1 — first visit, onboarding, first dashboard
Did: fresh context → `#/` redirects to `#/welcome` (about 0.2 s). Step 1 "How this works" → "Got it"; step 2 picked FAR first, looked at the discipline list, typed a past date (2026-01-01), Next, Back (date kept), then 2027-01-15; step 3 kept the default weekly minutes (8 h 30 min) → "Build my plan". Both viewports.
Worked: the gate redirect, three short steps, Back keeps values, the dashboard countdown ("100 days to FAR", long-form exam date), the diagnostic call-to-action, one "Study next" card, today's plan sized to the day's minutes, honest "Not enough data yet" readiness. No horizontal overflow on either viewport.
Didn't: the discipline list shows "BAR — BAR" / "ISC — ISC" (no content for those sections) — U-journeys-001. The date field has no `min` and accepts a past date without comment (consequences covered in journey 7). The status line mixes an ISO date ("finishes by 2026-11-22") with long-form dates elsewhere (cosmetic, not filed). `navigator.storage.persisted()` is false in headless Chromium (expected there; Settings shows it).
Screens: uj-j1-{d,m}-01…04.

## Journey 3 — module practice, mixed set, review queue
Did: tutor set from lesson completion: Q1 right/Confident (auto-advance after 1.5 s works), Q2 wrong/Unsure via keyboard (D then 2) + error tagger ("Concept gap" → "Logged."), Q3 right/Guess ("Correct — but you guessed…", no auto-advance), Q4 flag + note + strike-out, then reload (same question, flag kept, clock kept, 3/10 answered), Q4 right/Unsure, Q5 skipped, Q6–Q10 with one wrong. Results → reviewed a missed item. Mixed set (20) with every confidence rating. Custom Area I set, 4 questions, test mode, timed (06:00 shown = 4 × 90 s). Forced SRS items due (IndexedDB edit + reload) → Review → 18 due questions → answered half right. Flagged filter in the builder found the flagged item.
Worked: confidence prompt is clear; explanations show per choice; flags and notes persist; resume after reload is exact; mixed set from studied modules; test-mode navigator; review queue builds from missed/low-confidence items; pacing line on results.
Didn't: results undercount what entered review and say "Clean sweep" at 50% (U-journeys-005); test-mode "answered" count ignores confidence-less answers and Submit has no confirmation (U-journeys-006); a very fast letter-then-digit keypress drops the confidence (U-journeys-007, S4). The "Mixed practice" card promises interleaving, but with one studied module all 20 come from that module (expected given the data; not filed).
Screens: uj-j3-{d,m}-01…14.

## Journey 7 — planner, analytics, search, glossary, notes, settings, export/import
Planner edge cases (Settings → FAR date and sliders, then Home and Study plan; desktop, plus "tomorrow" on phone):
- Exam tomorrow (via onboarding): "1 day to FAR"; plan = today "Light review…", tomorrow "Exam day"; status "Your exam is tomorrow — too close…". But "Final review starts Mon, Oct 26" (a past date). Dashboard still offers the 60-minute diagnostic.
- Exam today: "0 days to FAR"; single "Exam day" card, sensible message.
- Exam 3 days out (6 h/day): status says focus on review, but the plan schedules a 4-hour mock today and ~15 new lessons/practice sets tomorrow → U-journeys-017.
- Exam in the past: dashboard "FAR study home" but "Exam on Sunday, October 18, 2026" with no warning; plan card "On track" + "has passed" → U-journeys-018.
- No date: rolling 28-day plan with "Set an exam date…" — fine.
- 1 h/week (Sunday only): "Behind by about 34 hours. Adding ~223 min/week…" — checked: shortfall 42 h 3 min − 7 h 39 min = 2,064 min over 65 days to final review → 2,064/65×7 = 222.3 → 223. Rest days shown as "Off · Rest day".
- 60 h/week: not possible — sliders stop at 6 h/day (42 h/week); with 42 h the plan is "On track", finishing new material 2026-11-10 → U-journeys-019 (S4). 800 days out: list capped at 400 days with no note (same finding).
Analytics after 5 answers: tiles, weakest area, by-area/skill/calibration/trend/error log/modules all render with no overflow on either viewport; the "Exam pace ≈ 144s" hint conflicts with the 90-second target used elsewhere → U-journeys-021.
Search: "deferred tax" 50 (cap), "ASC 842" 12, "goodwill impairment" 20, nonsense 0 with "0 result(s)"; a Question hit opens the module lesson, not the question → U-journeys-022 (S4).
Glossary: 38 FAR terms; filter "goodwill" → 1; "All sections" toggle works; lesson links present.
Notes: module note, saved highlight and a question note all listed under the module.
Settings: Dark theme and 120% text apply immediately (html.dark, 19.2px). Storage-persistence status shown honestly.
Export/import: JSON backup (10 tables: settings 1, attempts 5, srs 5, itemMeta 1, moduleProgress 2, highlights 1, quizSessions 1…) and CSV (header + 5 rows). ## Journey 8 — offline, PWA, reload mid-session, update prompt
Offline (both viewports): after first load + one reload the page is controlled by the service worker (workbox precache, 343 entries ≈ 9 MB incl. all four sections' content). `context.setOffline(true)` + reload: dashboard, course, an unvisited lesson (far-bonds, body loaded from cache), a new practice set, FAR and AUD simulations, flashcards, search, final review, the exam home and starting a new mock all worked; switching the active section to REG offline and opening a REG lesson worked; a brand-new tab opened offline cold-started from cache. No console errors. (Two "NOT OK" lines in logs/j8-run.txt are my selectors matching hidden elements; the page text shows the content loaded.) Mermaid: only `flowchart` diagrams are used and that engine is precached; the excluded diagram engines are not used by any lesson.
PWA: Chromium reports no installability errors (CDP Page.getInstallabilityErrors = []); manifest has name, short_name, standalone display, start_url/scope "/", 192/512 icons and a maskable icon. The real install prompt and standalone-window behaviour could not be exercised headless.
Reload mid-session (from journeys 3–6): quiz — same question, answers, flag, note and clock kept; TBS — entries and clock kept; mock — clock continues from the wall-clock deadline (3:59:55 → 3:59:51 across a 2 s wait + reload), answers and flags kept, testlet lock kept, break state and break timer survive a reload; lesson — scroll position restored; flashcards — grades are saved but the in-memory session queue is lost (the review page rebuilds what is still due).
Update prompt: read UpdatePrompt.tsx (registerType "prompt"; Reload withheld on /exam/, /quiz/, /tbs/). Triggered for real by serving the same dist/ from a tiny static server on :4173 that appends a comment to sw.js on demand (`scripts/bumpserver.cjs`; dist/ untouched; vite preview restored afterwards). Results: in a quiz and in a mock the toast says "You can reload once you finish or leave this session" with only "Later"; on the dashboard it offers Reload/Later; after Later it stays hidden during in-app navigation and returns after a reload (waiting worker persists); Reload activates the new worker and the in-progress mock is still resumable. Problems: on a phone the toast covers the quiz's sticky controls and bottom nav, and "Later" is ~1.7:1 contrast → U-journeys-023 (S2); no periodic update check → U-journeys-024 (S4).
Screens: uj-j8-{d,m}-01…06, uj-j8u-{d,m}-01…03.

## Console errors seen
None. No `console.error`, `console.warning` or `pageerror` events in any journey on either viewport (logs/*.log are empty; full stdout in logs/*-run.txt). The only failed requests were two lazy chunks (FlashcardPlayer, ReviewQueue) aborted with net::ERR_ABORTED when my script navigated and reloaded immediately (journey 3) — a test artefact, not an app error.

## Could not test / limits
- Real PWA installation, the standalone window, iOS Safari/WebKit behaviour (only Chromium was available; WebKit is not installed and `playwright install` is forbidden), and the native text-selection menu on touch devices (mobile highlights were created programmatically).
- Waiting out real time: the 4-hour mock timeout auto-submit, the 15-minute break expiry and the timed-set auto-submit were judged from code (ExamPlayer/QuizPlayer effects) rather than waited for; review-queue due dates were forced by editing IndexedDB.
- 60 h/week could not be entered (UI caps at 42 h/week; filed).
- Accessibility and performance are covered by the other reviewer (journeys 9–10); contrast is mentioned here only where it blocks a flow (U-journeys-023).

## Needs expert verification
None of the findings is low-confidence. U-journeys-023 is rated S2 with medium confidence (it is dismissible, but it hides core controls mid-session behind a near-invisible button); a reviewer could reasonably call it S3.
